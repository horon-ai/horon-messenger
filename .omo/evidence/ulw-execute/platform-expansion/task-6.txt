## Deliverable

Filled the skeleton `crates/providers/slackbot` crate. `SlackBotClient` (client.rs) drives
`https://slack.com/api` through `hyper-messenger-provider-common`'s `HttpClient`/`Request`.
Bot token `xoxb-...` from env `HYPER_MESSENGER_SLACKBOT_TOKEN` or `FileCredentialStore`
account `default`; prefix validated (else `Error::InvalidInput`). Base URL from env
`HYPER_MESSENGER_SLACKBOT_API_BASE`, default `https://slack.com/api`.

Operations mapped (no SEARCH_MESSAGES advertised):
  whoami         -> auth.test
  list_chats     -> conversations.list
  get_chat       -> conversations.info
  list_messages  -> conversations.history
  send_message   -> chat.postMessage (non-idempotent)
  list_members   -> conversations.members + users.info
  snapshot       -> auth.test + conversations.list
`AuthProvider` implemented (BotToken method, status/login/logout).

Slack returns HTTP 200 with `{ok:false,error}`; `check_response` maps `ok:false`/absent `ok`
to a typed Error: `invalid_auth`/`not_authed`/`account_inactive` -> AuthFailed, else Protocol.
No Socket Mode. No `anyhow` in the library. One-line public doc comments only.

## Risks / notes

- Requests use POST with a JSON body for every endpoint. Slack accepts JSON bodies for these
  classic Web API methods; the mock accepts any body. Form-encoding was not needed.
- `list_members` fails fast if any single `users.info` call fails (one bad member aborts the list).
- Timestamps parse the integer-seconds part of Slack's `ts`; sub-second precision is kept to ms.
- The workspace `Cargo.lock` changed because `chrono` was added to the slackbot crate.
- No commit made (per task instruction).
