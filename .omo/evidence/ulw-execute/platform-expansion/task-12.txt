DESIGN NOTES
------------
- Client uses `hyper-messenger-provider-common`'s `HttpClient`/`Request` over
  `https://i.instagram.com/api/v1` (env override `HYPER_MESSENGER_INSTAGRAM_API_BASE`).
- Auth: `sessionid` / `ds_user_id` (optional `device_id`, `csrftoken`) read from env
  (`HYPER_MESSENGER_INSTAGRAM_SESSIONID`, `HYPER_MESSENGER_INSTAGRAM_DS_USER_ID`,
  `HYPER_MESSENGER_INSTAGRAM_DEVICE_ID`, `HYPER_MESSENGER_INSTAGRAM_CSRFTOKEN`) or the
  `FileCredentialStore` account `default`.
- Headers per the reference: `User-Agent` (`Instagram 428.0.0.47.67 Android (...)`),
  `X-IG-App-ID: 567067343352427`, `X-IG-WWW-Claim`, `IG-INTENDED-USER-ID`,
  `X-IG-Device-ID` (when set), `Cookie: sessionid=..; ds_user_id=..[; csrftoken=..]`.
- Every request is wrapped in a 30s `tokio::time::timeout`; a stall maps to a typed
  `Error::Network` ("timed out ... IP may be flagged") because flagged IPs hang silently.
- Send is non-idempotent (`Request::post`, never retried after transmission).
- Operations: whoami, list_chats, get_chat, list_messages, search_messages, send_message,
  list_members, snapshot. `AuthProvider` implemented (methods = [Extract]).
- Not implemented (out of scope): MQTT realtime, browser token extraction.

RISKS / LIMITS
--------------
- The POST body is sent as a JSON-encoded string carrying the IG form payload
  (`thread_ids=..&text=..&action=send_item&client_context=..`) because the shared
  `HttpClient` always serializes via `reqwest::json()` and forces `Content-Type:
  application/json`; it cannot emit `application/x-www-form-urlencoded` without changing
  the common crate (out of scope). The mock parses both. A real IG endpoint may reject the
  content-type.
- `whoami` hits `/accounts/current_user/?edit=true`; unlike the TS reference (which reads the
  stored account) it needs the network, so it fails when only credentials are present offline.
- Realtime (MQTT) and browser token extraction are intentionally not implemented.
- Two workspace deps added to the crate (chrono for microsecond timestamps, uuid for
  `client_context`); Cargo.lock updated accordingly.
