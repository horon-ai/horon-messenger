## Adversarial classes

- malformed input (missing fields -> Protocol): `decode::<SlackAuthTest>` on
  `{"ok":true}` yields `ErrorCode::Protocol`
  (test `missing_required_field_decodes_to_protocol`); a body with no `ok` field is
  Protocol (test `ok_true_passes_and_missing_ok_is_protocol`).
- misleading success (`ok:false` at HTTP 200 must be an error): `check_ok` maps
  `invalid_auth` -> AuthFailed, `channel_not_found` -> NotFound, `ratelimited` ->
  RateLimited, unknown -> Protocol (test `ok_false_at_http_200_maps_to_typed_errors`);
  the QA harness proves it end to end (mock returns HTTP 200 + invalid_auth when the
  `d=` cookie is absent, CLI surfaces `error.code == AUTH_FAILED`).
- others n/a: no RTM/QR login in scope; the only non-idempotent call is
  chat.postMessage, which the common client already refuses to auto-retry (covered by
  provider-common's own tests).

## Risks / limitations

- The `d=` cookie is optional in the client: a present token alone builds the request,
  and a missing cookie is surfaced by Slack as `invalid_auth` -> AuthFailed (this is
  what the QA's missing-cookie case asserts). A cookie is required by `auth login`.
- list_chats paginates conversations.list at limit=200 per page; list_members
  paginates conversations.members and does one users.info per member (N+1).
- search_messages is global (`search.messages`); when a chat id is supplied it is
  recorded as the page's chat_id, but the query is passed to Slack unchanged.
- `sent_at` for sent messages and messages uses the Slack `ts` string (Slack ts is not
  RFC3339); SendResult.sent_at is stamped with `now_rfc3339`.
- Base URL and credentials come from env/store only; no RTM or QR login implemented
  (out of scope).
